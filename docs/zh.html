测试通过，是一个时刻。
不是永远有效的状态。

代理暂停了，同伴提交了修改，新会话开始了。聊天里写着「测试已通过」。但通过测试的，到底是哪一个版本？

Phoenix 把命令执行结果与当时的 Git 状态、跟踪文件快照关联起来。上下文变化时，它会解释旧记录为什么不再匹配。

01 / 记录

保留运行结果。

执行你明确指定的命令，在本地保存退出结果和文件指纹。

02 / 比较

核对当前上下文。

把记录与恢复工作时的仓库比较。检查过程不会运行记录中的命令。

03 / 理解

看清变化原因。

查看变化路径，以及 PASS、REVIEW 或 BLOCK 的具体原因。

少一点猜测，多一点依据。

四个关键时刻。

示例回放 此处不会上传或执行代码。
一个重要区别

BLOCK 不一定表示代码有错。也可能只是旧的成功记录，已经不能代表现在的代码。

清楚边界，才能建立信任。

知道它检查什么。
也知道哪些仍待验证。

+

让证据带上上下文。

  • 明确指定的命令及其退出结果
  • Git HEAD 和跟踪文件指纹
  • 变化文件路径与工作区状态
  • 由你自己保管的本地记录
−

保留必要的不确定性。

  • 不证明测试充分性或代码正确性
  • 不分析测试依赖，也不建议跳过测试
  • 不核验被忽略的文件或环境变化
  • JSON 记录可以编辑，不是防伪凭证
