A SMALL CHECK. A CLEARER HANDOFF.

A passed test is a moment.
Not a permanent state.

An agent pauses. A teammate commits a change. A new session begins. The conversation says “tests passed.” But which version passed?

Phoenix connects a recorded command result to its Git and tracked-file snapshots. When that context changes, it tells you why the old result no longer matches.

01 / CONFIGURE

Name the check.

Review its command, timeout and repository scope. Each named check keeps separate local evidence.

02 / REFRESH

Record an explicit run.

Run one check you choose. Its latest attempt becomes current, including failures and timeouts.

03 / INSPECT

Check before continuing.

Status compares the current code with that evidence. It does not rerun tests or retry automatically.

THE IMPORTANT DISTINCTION

BLOCK doesn’t mean your code is broken. It can mean an old successful run no longer describes your current code.

CONFIDENCE STARTS WITH HONEST LIMITS.

Know what it checks.
And what it doesn’t.

+

Evidence, with context.

  • Named checks bound to reviewed command definitions
  • Explicit execution results, Git and tracked-file snapshots
  • Changed paths and separate PASS, REVIEW or BLOCK outcomes
  • Local CLI/JSON and same-job GitHub Actions integration
−

Not a safety guarantee.

  • No proof of test quality or code correctness
  • No automatic retry, dependency analysis or test-skipping advice
  • No verification of ignored files or environment changes
  • Editable local records; no cross-machine or cross-job attestation
