# MIT core and scoped paid services / 商业结构

The project owner selected MIT licensing on 2026-11-13. The current licensed tree
and its package include [LICENSE](LICENSE). This notice does not rewrite old
release attachments. The copyright holder is identified by the repository owner's
public GitHub handle; no separate company identity is asserted.

The MIT core can be used commercially, modified and redistributed subject to its
license notices. No payment, activation server, API key or subscription is required
for core commands. Customers are not charged for permissions they already receive
under MIT, and no proprietary rights to MIT-covered core code are promised.

Potential revenue is a separately agreed **fixed-scope integration/customization
delivery plus time-limited support**. No customer, payment, contract or fixed price
is evidenced by this document. It is a proposal outline, not an executed agreement,
legal advice, warranty, response-time promise or production SLA.

## A possible first paid delivery

- One authorized non-critical repository and one named supported workflow.
- Reviewed check configuration, explicit refresh and status integration, explanation
  of passing, stale, failed, timed-out and interrupted-state behavior.
- Acceptance examples, installation/rollback instructions, and an identified owner
  who can operate the integration after handoff.
- A written support period with a clear start/end, covered issue types, support
  channel and limits; extensions/new features require a separate agreement.

Before work starts, both sides must specify the buyer and delivery/payment
responsible parties, exact scope, price/payment milestones, acceptance procedure,
support terms, data access and treatment of any custom deliverable's license.
These are unresolved per-client decisions, not defaults imposed by this file.

## Never implied by a paid pilot

- Guaranteed prevention of bugs, data loss, unsafe agent actions or deployment
  incidents; guaranteed savings, revenue or business results.
- Authenticated/fraud-proof evidence, cross-machine coordination, universal
  framework compatibility or observation of all environment/background changes.
- Unlimited customization, perpetual upgrades, round-the-clock support or access
  to customer secrets. Production rollout needs its own review and approval.

Customers may conclude their existing Git/CI tooling is sufficient. Record that
result honestly. A paid pilot is appropriate only for a concrete need with an
authorized buyer and an agreed acceptance scope, not because a demo passed.
